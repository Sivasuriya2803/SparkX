# SparkX
RevCast-Automated Revenue Forecasting System



Hackathon Challenge Rated Revenue Forecasting System

1. Executive Summary & Business Problem

Currently, our delivery and management team perform revenue forecasting manually using disparate spreadsheets every week. This process is time-consuming, prone to human amar and makes tracking weekly changes (variance) difficult

The goal of this hackathon is to build RevCast, a centralized web application that automates revenue forecasting. The application will ingest resource data, apply complex real-world billing logic (including leaves, resignations, and backfil overlaps), and generate dynamic monthly and quarterly revenue projections, eliminating manual weekly spreadsheet maintenance

2. User Personas

Your application must cater to the following user roles, each requiring different levels of data aggregation (Project vs. Segment vs. Account level):

Project Managers (PMs): Update resource data, log leaves, manage replacements, and view project-level forecasts.

Project Directors/Delivery Heads: View aggregated forecasts across multiple projects and programs.

3. Core Functional Requirements & Business Rules

To build an accurate engine, your application must implement the following business logic:

A. Revenue Types & Resource Lifecycle

SBL (Soft Backlog): Revenue generated by resources currently assigned and active in the system.

STBO (Sold To Be Offered): Revenue projected for open positions currently being staffed.

The Transition Rule: When a concrete Start Date is assigned to an STBO resource, their revenue type automatically converts to SBL.

B. Leave Adjustments (New Rule)

The Leave Factor: The system must allow PMs to capture the number of planned leaves for a resource in any given month.

The calculation engine must deduct these leave days from the total billable days of that month to ensure the forecast reflects true billable hours.

(Monthly Billable Days) = (Standard Working Days in Month)- (Planned Leaves)

C. Resignations, Backfills & Overlap Billing (Updated Rule)

When a resource resigns or is released, the system must capture their Last Working Day (LWD). Revenue forecasting for this resource stops after this date.

If a backfill is requested, an STBO entry is created.
